# ReBoot モデルビューア

PlayStation 版『ReBoot』（SLUS-00274）のディスクイメージを読み込み、キャラクターの3Dモデルをブラウザで回して見るビューア（非公式）。

**https://haristweet.github.io/reboot-model-viewer/**

## 使い方

1. 手持ちの ReBoot（SLUS-00274）のディスクイメージをページにドロップするか、「ファイルを選ぶ」で選ぶ
   - `.chd`（MAME の圧縮形式・v5）
   - `.bin`（2352バイト/セクタの生イメージ、または 2048バイトの ISO）
2. 左（スマホは下のタブ）でキャラクターと動きを選ぶ。再生・停止、コマ送り、速さを変えられる
3. ドラッグで回転、右ドラッグ／Shift＋ドラッグで移動、ホイールで拡大、ダブルクリックで元に戻す
   （スマホは2本指で移動と拡大、ダブルタップで元に戻す）
4. キーボードは ← → でコマ送り、スペースで再生／停止、`r` で視点を戻す

できること:

- 背景の色を8色から選べる（次に開いたときも覚えている）
- スクリーンショット、動画（MP4／WebM）、アニメーションPNG で保存できる。
  「背景なし」で透過、「切り抜き」でキャラクターの周りだけ。スマホでは共有シートから写真に保存できる
- BGM を鳴らせる（8曲）。生セクタが読めるイメージ＝ `.chd` か 2352バイト/セクタの `.bin` のときだけ

面の向きは全モデルでそろっている（共有する辺が必ず逆向きにたどられる）ので、裏を向いた面は描いていない。

### 左右の向き

**外向き＝反時計回り**（符号付き体積が正）。実機の表示リストを見ると、**描かれた三角形は
全部、画面（Yは下向き）での外積が負**だった（BOBGUN で 566/566）。
これは「左右を反転しない投影」がちょうど出す符号なので、実機は反転していない。

モデル座標は **左＝+x / 上＝−y / 前＝−z**。裏づけは3つあって、どれも同じ答えになる。

1. 関節名。銃は `r_hand` の子（`firstbrta` / `secndhcklr`）で、その `r_hand` は x が負、`l_hand` は正
2. 上着の文字。背中の `01` と `ENZO`、胸の `01` が、反転しない描き方のときだけ正しく読める
3. 上の実機の符号

### 体は「ふたの無い筒」の集まり

関節ごとのパーツは**どれも閉じていない**（`m_torso` は縁が20本、腕は11本ずつ空いている）。
重ねて隠す作りなので、関節が曲がると腰や肘に隙間が出る。データどおりで、埋める面は存在しない。

ゲームのデータはこのページに一切含まれていない。読み込んだファイルはブラウザの中だけで読み取り、どこにも送信しない。

## 中身

`index.html` の1枚のみ。外部ライブラリもビルドも無い（WebGL 直書き）。

- ディスク: ISO9660 を読んで `SYSTEM.CNF` を確認し、`ANIMATE/` と `DATA/` から必要なファイルだけ取り出す
- CHD: ハンクの目次（ハフマン符号）を解き、`cdlz`（LZMA）と `cdzl`（Deflate）のハンクを展開する
- BGM: `MOVIES/MUSIC.WXA` の XA-ADPCM を解いて Web Audio に流す

## データの形

解析は実機（DuckStation）のメモリと表示リストを突き合わせて確かめた。

### `.TOM`（モデル）

ヘッダの大きさは `+0x00`（224 / 248 / 252 の3種類）。件数がまとまっている所は「ヘッダの大きさ − 0x1c」、テクスチャ名は「ヘッダの大きさ」から。

| 位置 | 中身 |
|---|---|
| +0x08 / +0x0c | 頂点の位置 / 頂点数（1点 = int16 x,y,z + 余り） |
| +0x10 / +0x14 | 面の位置 / 面数（1面 26バイト） |
| +0x18 / +0x1c | 関節表の位置 / 関節数 |
| +0x40〜0x60 | 節の位置 9個 |
| +0x64〜 | 関節ごとの面数（描画の順） |

関節レコードは刻みが 0x40 と 0x58 の2種類あり、名前の位置も +0x20 と +0x38 の2通り。

**26バイトの面データにある頂点番号とUVは使われていない**（モデラー側の名残り）。実際に使うのは節の中。

| 節 | 中身 |
|---|---|
| 0 | 面数ぶんの4バイト表が3枚。表0の `(a,b,c,0)` が **その面の3つの角が読む置き場の番号** |
| 1〜3 | 面ごとの RGB（節1の4バイト目は 0x34 ＝ POLY_GT3） |
| 4〜6 | 面ごとの **(u,v)** ＋ 上位2バイトに **テクスチャ名の4文字**（実機では CLUT / TPAGE に書き換わる） |
| 7 | 頂点ごとの **置き場の番号**（値÷4）。関節が持つ頂点を並べた順で引く |
| 8 | 関節への飛び先の並び（描画の順＝末端から根へ） |

組み立て方: 面の束（関節）を順に処理し、その関節の頂点を `置き場[節7[k番目]/4]` に書いてから、束の面の角を `置き場[節0表0[f] の c バイト目]` で読む。置き場は数十個しかなく束をまたいで使い回されるので、2周まわしてから面を出す。

### `.NAN`（動き）

`keys[コマ] = (ポーズ番号, 時刻 0〜127)`。ポーズ i と i+1 を 時刻/128 で混ぜる。ポーズは関節ごとの四元数（w,x,y,z の int16、1.0 = 16384）。

姿勢: 子の位置 = 親の位置 ＋ **親の向き** × 子の `pos`／子の向き = 親の向き × 子の四元数。四元数は根からたどった順に消費する。

### `.PSH`（テクスチャの束）

```
"SHPP" | 大きさ | 件数 | "GIMX" | (名前4文字, 位置)×件数 | 中身
中身1件 = 16Bの頭（旗 / 幅 / 高さ / 0 / VRAM位置）＋ 画素 ＋ CLUT の塊
```

- 旗の下位バイトが種類（`0x40` 画像 / `0x23` CLUT）
- **旗の上位16ビットは「256バイト単位に切り捨てた大きさ」**。色の深さの判定にだけ使い、
  画素の量は `幅 × 高さ × bpp / 8` で数える。切り捨てた値をそのまま使うと、
  半端な大きさの画像（32×43 など）で足りなくなり、直後の CLUT も見失う
- CLUT は画像の直後とは限らないので、**ファイル全体から CLUT の塊を拾い、画像より後ろの最初のもの**を使う
  （この方法で全 .PSH の画像 3672 件すべてに CLUT が付く）
- CLUT は PS1 の BGR555 で、色番号0は透明
- VRAM位置は実機の配置そのままで、読み込み時の詰め直しは無い
- UV は 0〜255 の正規化で、画素は `u × 幅 / 256`

### `MUSIC.WXA`（BGM）

ディスクの `MOVIES/` にある。中身は生の CD-XA セクタ（Mode2 Form2）で、
**8曲を1セクタずつ交互に**並べてある。曲＝セクタ位置 % 8。

- ステレオ・4ビット・37800Hz（サブヘッダの coding = `0x01`）
- 1セクタ = 18グループ × 4組 × 28サンプル = 2016フレーム
- サブヘッダの「音声」ビット（`0x04`）が落ちた所が曲の終わり。8曲とも 85〜95秒
- 復号はPS1と同じ4次フィルタ（係数 0,60,115,98,122 / 0,0,-52,-55,-60）

2048バイト/セクタの ISO には生セクタが無いので、その場合 BGM 欄は出ない。

なお `DATA/SOUND/STREAMS/ROB.BIG` は BGM ではなく**音声（せりふ）**で、
EA の `SCHl` / `SCCl` / `SCDl` / `SCEl` 形式の塊が748本入っている（PS1 の16バイト枠 ADPCM）。
効果音と楽器は `DATA/SOUND/*.BNK`（`BNKl` 形式）。

## 動きファイルの選び方

`.TOM` と同じ名前の `.NAN` があっても**関節数が合わないことがある**（`RBINOM` はモデル21・動き20、
`ZBINOML` はモデル8・動き20）。逆に `DOTGUN` `DOTCANON` `ENZOGUN` `ENZOCAN` `VBINOM` `CIVIL` `BOB` は
自前の `.NAN` が無い。

なので**関節数が一致するものだけを候補にして、名前の一致が長い順・動きの多い順**で選ぶ。
借りた場合は画面に「動きは ○○ のものを借用」と出る。

| モデル | 借りる動き |
|---|---|
| DOTGUN / ENZOGUN / VBINOM | BOBGUN |
| DOTCANON / ENZOCAN | BOBCANON |
| CIVIL | ZBINOM |
| BOB | BOBTABLE |
| RBINOM | RBINOML |
| ZBINOM | ZBINOML |
| ZBINOML | CBINOM |

`GBINBOD` だけは関節9で一致するものが無く、動きが付かない。

## 使われていないモデル

ステージのプログラム `LEVELA.OVL` に **読み込むモデルのファイル名が全部書いてある**
（`ANIMATE\bobcanon.tom` の形）。ここに無いものは一覧で「未使用」と出る。

`BOB` `BOB2` `ENZO` `CADDIE` `GBINBOD` `TENTACLE` `ZBINOML` の7体。
ゲームが操作するのは武器を持った `BOBGUN` / `BOBCANON` / `ENZOGUN` / `ENZOCAN` の方。
`ZBINOML` と `GBINBOD` は関節表も他と食い違っていて、まともな姿勢にならない。

## テクスチャが欠けているモデル

`BOB` `CIVIL` `CLASH` `DOTCANON` `GBINBOD` `RBINOM` は、モデルが指しているテクスチャ名が
**ディスクのどこにも入っていない**（全 .PSH の1392件を大文字小文字・1文字違いまで探して無し）。
その面は灰色で出る。一覧では名前の後ろに「（テクスチャ欠け）」と付く。

`BOB` は古い版らしく、テクスチャ名が全体的に別物（`BHRB` / `Brfl` / `bck1`。
ゲームが使う `BOB2` `BOBGUN` `BOBCANON` は `bhrb` / `Brf1` / `legs`）。

## 分かっていないこと

- 面の種類（u16）の上位バイト。材質番号ではない（テクスチャ枚数を超える）
- 節0の表1・表2（1面1個、値は置き場の番号と同じ範囲）
- `TENTACLE` は関節表の並びが特殊で読めない。`GBINBOD` は一部の面が落ちる
